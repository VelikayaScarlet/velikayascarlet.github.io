## 一、设计目标

新版身份证号码希望满足以下约束：

- **有规律**：号码结构固定，可按字段解析。
- **有规则**：每一段都有明确生成逻辑。
- **可验证**：能检查字段格式、生日编码是否有效，并通过数据库检查唯一性。
- **保留生日信息**：号码中仍然可以恢复完整出生日期。
- **不编码性别**：号码本身不泄露性别。
- **不编码市/县级户籍信息**：不再像现行身份证号那样暴露细粒度籍贯。
- **尽量紧凑**：允许使用字母，通过 Base36 等方式压缩长度。

---

## 二、总体结构

采用 **11 位**：

```text
PP BBBB NNNN C
```

写成连续形式：

```text
PPBBBBNNNNC
```

其中：

| 字段 | 长度 | 字符集 | 含义 |
|---|---:|---|---|
| `PP` | 2 | 十进制数字 | 省级代码 |
| `BBBB` | 4 | Base36 | 出生日期编码 |
| `NNNN` | 4 | 十进制数字 | 个人区分码 P |
| `C` | 1 | Base36 | 随机消重码 |

总长度：**11 位**。

---

## 三、省级代码 `PP`

保留两位省级行政区代码，但**不继续编码市、县级行政区**。

例如：

```text
41 = 河南
31 = 上海
```

设计目的：

- 保留一个粗粒度的登记区域信息；
- 避免现行身份证号暴露到市、县级户籍来源；
- 省级代码固定为两位，结构简单。

---

## 四、生日编码 `BBBB`

### 4.1 编码方式

先计算出生日期距离：

```text
1900-01-01
```

的天数 `D`，然后把 `D` 转换成 **Base36**，不足 4 位左侧补 `0`。

Base36 字符集：

```text
0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZ
```

即：

```text
0–9 = 0–9
A–Z = 10–35
```

### 4.2 示例

出生日期：

```text
2002-08-16
```

距离 1900-01-01：

```text
D = 37482
```

转换为 Base36：

```text
SX6
```

补齐 4 位：

```text
0SX6
```

因此：

```text
2002-08-16 → 0SX6
```

### 4.3 可支持日期范围

4 位 Base36 一共可以表示：

```text
36^4 = 1,679,616
```

个不同数值。

以：

```text
1900-01-01 = 0
```

为起点，则最大可表示天数为：

```text
1,679,615
```

因此理论日期范围约为：

```text
1900-01-01 ～ 6498-08-18
```

如果制度实际只允许 1900–2099，则应在验证阶段额外限制合法日期范围。

### 4.4 解码方式

```text
Base36(BBBB) → D
1900-01-01 + D 天 → 出生日期
```

因此生日字段是**可逆编码**，不是哈希。

## 五、个人区分码 `NNNN`

记作 `P`。

长度：

```text
4 位十进制数字
```

范围：

```text
0000–9999
```

生成公式：

```text
P = (YYYYMMDD + T) mod 10000
```

其中：

- `YYYYMMDD`：出生日期按八位十进制表示；
- `T`：**首次登记时的 Unix 毫秒时间戳**；
- 最终结果不足 4 位时左侧补 `0`。

例如：

```text
P = 37
```

号码中写成：

```text
0037
```

#### 设计含义

`P` 用来区分：

- 同一省份；
- 同一天出生；
- 不同登记个体。

它不代表：

- 性别；
- 出生顺序；
- 城市；
- 户籍类别。

---

## 六、消重码 `C`

最后一位 `C` 使用 **1 位 Base36**：

```text
0–9 / A–Z
```

共：

```text
36 种可能
```

### 6.1 生成方法

`C` **随机生成**。

完整号码生成后，在数据库中检查：

```text
PPBBBBNNNNC
```

是否已经存在。

如果发生完整号码碰撞：

```text
重新随机生成 C
```

直到号码唯一。

### 6.2 含义

`C` 仅承担**消重**作用，不编码任何个人属性。

特别是不表示：

- 性别；
- 登记顺序；
- 户籍；
- 年龄；
- 地域层级。

---

## 七、完整号码的生成流程

假设某人：

```text
省份：河南
生日：2002-08-16
```

则：

### Step 1：省级代码

```text
河南 → 41
```

### Step 2：生日

```text
2002-08-16
→ 距 1900-01-01 共 37482 天
→ Base36 = SX6
→ 补齐 = 0SX6
```

### Step 3：生成 P

```text
P = (20020816 + 首次登记 Unix 毫秒时间戳 T) mod 10000
```

假设结果为：

```text
5821
```

### Step 4：随机生成 C

例如：

```text
C = Q
```

最终号码：

```text
410SX65821Q
```

> 此处 `5821` 和 `Q` 只是格式示例；正式号码必须由登记时的时间戳与随机消重流程生成。

---

## 八、验证规则

### 8.1 长度与字符格式

必须恰好：

```text
11 位
```

并满足：

```text
PP    = [0-9]{2}
BBBB  = [0-9A-Z]{4}
NNNN  = [0-9]{4}
C     = [0-9A-Z]
```

### 8.2 省级代码验证

检查 `PP` 是否属于合法省级代码表。

### 8.3 出生日期验证

将 `BBBB` 从 Base36 转成整数 `D`：

```text
date = 1900-01-01 + D days
```

检查日期是否在制度允许的日期范围内。

### 8.4 唯一性验证

最终号码必须在中央登记数据库中进行唯一性检查：

```text
UNIQUE(PPBBBBNNNNC)
```

`C` 的作用是在极少数发生碰撞时进一步消重。

---

## 九、隐私设计

新版号码刻意取消了现行身份证号中容易直接推断的部分信息。

### 不再编码

```text
市级户籍
县级户籍
性别
同日出生顺序
```

### 仍然编码

```text
省级登记代码
完整出生日期
```

其中生日仍属于直接可恢复的个人信息，这是该方案有意保留的功能，而不是隐私隐藏字段。

---

## 十、当前方案摘要

```text
PPBBBBNNNNC
```

即：

> **2 位省级代码 + 4 位 Base36 生日 + 4 位十进制个人区分码 + 1 位 Base36 随机消重码。**
